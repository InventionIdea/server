# MSA에서 모듈러 모놀리스로의 전환

## 1. 배경
초기 프로젝트는 백엔드(Spring Boot)와 AI 영상 처리(FastAPI)를 분리한 MSA 구조로 설계함.
- 원래 계획은 스테이블 디퓨전(Stable Diffusion) 같은 무거운 모델을 GPU 컨테이너에서 직접 돌리려 했기 때문에, 확장을 고려해 서버를 분리했었음.

## 2. 문제점
- **비용 문제**: 팀 자금 사정상 GPU 컨테이너를 유지하는 것이 불가능함.
- **오버엔지니어링**: 결국 자체 모델 구동 대신 외부 무료 API를 사용하는 방식으로 노선을 변경함. 이렇게 되니 굳이 비싼 리소스를 쓰며 별도 FastAPI 서버를 유지할 이유가 사라짐.
- **운영 복잡도**: 단순한 API 호출 로직을 위해 두 개의 서버를 관리하고 통신시키는 것은 비효율적임.

## 3. 결정
**MSA 구조를 폐기하고, Spring Boot 단일 모놀리스 구조로 통합함.**
- Python 코드는 Spring Boot 프로젝트 내부의 스크립트(`scripts/`)로 옮기고, Java의 `ProcessBuilder`로 실행하는 방식 채택.

## 4. 결과
- 운영 비용을 획기적으로 절감함.
- 배포 파이프라인이 단순해지고, 관리 포인트가 하나로 줄어듬.
